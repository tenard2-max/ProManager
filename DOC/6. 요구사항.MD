# [템플릿] 프로젝트 요구사항 · 관제 서버 연동

**관제 플랫폼 표시명:** Central-Agent Orchestration (AI 관제 에이전트)  
**문서 역할:** 신규 프로젝트를 맡은 **구현 에이전트(Cursor IDE)** 에게 전달하는  
**최종 요구사항 + 관제 연동 지시서** 템플릿.  
**작성일:** 2026-11-16 · **버전:** v2.2 (SSOT: `{PROJECT_ROOT}/docs/`)

> 이 문서는 특정 제품(예: XFS/tetris)에 묶이지 않는다.  
> **새 프로젝트가 생길 때마다 본 파일을 복사·기입**하거나, 아래 공란을 채운 뒤 해당 에이전트에게 넘긴다.  
> 런타임 진행 상태 파일이 아니다.  
> **상태 SSOT는 해당 GitHub/제품 프로젝트의 `docs/`** (`spec.ini` · `project_status.ini`) 이다.

## 0. 에이전트에게 주는 한 줄 지시

```text
이 문서의 「1. 프로젝트 정체성」을 채운 뒤,
반드시 기동 중인 관제 서버(http://127.0.0.1:18765)에 SPEC_RESET으로 등록하고
HEARTBEAT·STATUS_UPDATE로 보고하면서만 개발한다.
코드만 작성하고 관제에 보고하지 않는 진행은 금지한다.
```

## 2. 근거 문서 (공통 참조)

| 문서 | 역할 |
|------|------|
| `{PROJECT_REQUIREMENTS_MD}` | **해당 프로젝트** 기술·기능 요건서 (제품마다 다름) |
| `DOC/3. [개발 요건서] 에이전트 감시 관제 시스템 …` | 관제 서버·INI 스키마·UI·감시 지표 **공통 원천** |
| `DOC/4. [추가 요건] 신규 개발 ↔ 관제 에이전트 연동.md` | 착수·SPEC_RESET·STATUS_UPDATE·HEARTBEAT·ACK **작업 의무** |

| **본 문서** | 이 프로젝트의 **발주자 최종 합의·연동 지시** (에이전트 전달용) |

1. 연동·보고 절차 → `DOC/4` + 본 문서 3~5절  
2. 제품 기술 내용 → `{PROJECT_REQUIREMENTS_MD}`  
3. 관제 프로토콜·스키마 → `DOC/3`

## 3. 관제 에이전트와 함께 개발 (필수 · 모든 프로젝트 공통)

1. 관제(`monitor_agent`, `127.0.0.1:18765`)에 **연결·보고하면서** 개발한다.
2. 관제 미기동·미등록 상태에서 대규모 구현을 진행하지 않는다.
3. 참고 클라이언트: `monitor_agent/tools/agent_client.py`
4. 발주자는 관제 UI로만 지시·승인한다. Cursor / 그록 봇은 관제 메시지를 따른다.
5. 상태의 단일 원본(SSOT)은 **`{PROJECT_ROOT}/docs/`** 이다.  
   - `docs/spec.ini` — 요건  
   - `docs/project_status.ini` — 진행·QA  
   `monitor_agent/data/` 또는 프로젝트 루트에 상태 INI를 **이중 원본으로 두지 않는다.**  
   (FS 뷰어는 이 `docs` 폴더를 선택한다.)

## 4. 연결 우선 워크플로 (Connection-first)

```text
[1] 관제 서버 기동 확인 (http://127.0.0.1:18765 / run_server.bat)
[2] 본 문서 1절 기입 + 개발 요건서 → REQ_* INI 매핑
[3] SPEC_RESET 으로 관제에 프로젝트·항목 등록
[4] HEARTBEAT 유지 → Cursor ONLINE 확인
[5] 구현 시작 (STATUS_UPDATE로 진행 보고)
[6] 자가 검증 완료 → IN_REVIEW + progress=60 + dev_note
[7] 그록 QA_RESULT → (필요 시) 재작업 → 발주자 최종 승인(VERIFIED)
```

**연결·보고 DoD**

- [ ] 대시보드에 **프로젝트 메인 제목**이 헤더에 보인다.
- [ ] `SPEC_RESET` 후 등록한 모든 `REQ_*`가 UI에 보인다.
- [ ] Cursor HEARTBEAT로 ONLINE이 유지된다 (권장 30초, 90초 끊기면 OFFLINE).
- [ ] 작업 시작/완료 시 `STATUS_UPDATE`가 이력에 남는다.
- [ ] outbox 명령에 `ACK`한다.
- [ ] Cursor가 progress>60 또는 `VERIFIED` / `qa_*`를 직접 쓰지 않는다.

## 5. 개발 중 보고 규칙 (공통)

| 시점 | 메시지 | 규칙 |
|------|--------|------|
| 요건 등록/변경 | `SPEC_RESET` | `payload.spec_ini` 전문, `spec_version` 증가 |
| 항목 착수 | `STATUS_UPDATE` | `status=IN_PROGRESS`, **progress ≤ 60** |
| 자가 검증 완료 | `STATUS_UPDATE` | `status=IN_REVIEW`, **progress=60**, `dev_note`에 증빙 |
| 상시 | `HEARTBEAT` | Cursor ONLINE 유지 |
| 명령 수신 | `ACK` | outbox `msg_id`를 `ack_for`로 응답 |
| QA | `QA_RESULT` | **그록 봇만** 수행 (Cursor 금지) |

**Cursor 금지**

- progress **61 이상** (REJECT)
- `status=VERIFIED` 직접 설정
- `qa_status` / `qa_score` / `qa_rework_count` 직접 설정

**작업 우선순위:** 발주자 `COMMAND` > `REWORK_REQUESTED` > `TODO` > `IN_PROGRESS`

**그록 QA (참고):** 합격 시 progress = `80 + round(qa_score × 0.2)`.  
불합격 시 `FAILED_REWORK` → `REWORK_REQUESTED`, progress=60, 반려 횟수 +1.

## 9. 관제 등록 항목 `REQ_*` (공란 · 신규 시 채움)

섹션 ID는 `REQ_001`부터 고유하게 부여한다. (`TASK_01` 형식 금지)

| ID | 제목 | category | priority | acceptance_criteria | target_files |
|----|------|----------|----------|---------------------|--------------|
| REQ_001 | `{TITLE}` | `{CAT}` | HIGH/MEDIUM/LOW | `{검증 가능한 한 줄}` | `{경로}` |
| REQ_002 | | | | | |
| REQ_003 | | | | | |
| … | | | | | |

**INI 골격 (SPEC_RESET용)**

```ini
[META]
project_name = {PROJECT_TITLE}
spec_version = 1
spec_source = {PROJECT_ROOT}/docs/
submitted_by = cursor
submitted_at = {ISO8601}

[REQ_001]
title = {TITLE}
category = {CAT}
priority = HIGH
spec_ref = {절 번호}
acceptance_criteria = {검증 가능한 한 줄}
target_files = {경로}
```

> `acceptance_criteria`에 `%`를 쓸 경우, 관제 파서는 `ConfigParser(interpolation=None)` 전제다.

## 11. 통합 수용 기준 (DoD · 공통)

1. 본 문서 1절·9절이 해당 프로젝트 값으로 기입되어 있다.
2. 관제 UI에 **프로젝트 메인 제목**이 헤더에 명확히 보인다.
3. 개발은 관제 연결 후(`SPEC_RESET` + HEARTBEAT ONLINE)에만 진행한다.
4. Cursor는 progress≤60만 보고하고, VERIFIED/qa_*는 설정하지 않는다.
5. 상태 SSOT는 `{PROJECT_ROOT}/docs/` (`project_status.ini`) 이며 다른 경로에 이중 보관하지 않는다.
6. 제품 고유 DoD는 `{PROJECT_REQUIREMENTS_MD}`를 따른다.
7. QA·최종 승인은 그록 봇 + 발주자 UI 경로를 따른다 (`DOC/6. 요구사항 - 봇.MD`).
